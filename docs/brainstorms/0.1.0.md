# Brainstorm — 0.1.0

目标:四项核心(建库、带出处的讲解、出题与错题、按遗忘风险复习),做深不做大。设计总纲见 `docs/DESIGN.md`。

## 1. 关键事实(已核实)
- DT 的 `compute_mastery` 是纯函数(`learning/mastery.py`),可直接移植。
- DT 的调度器 `SpacedRepetitionScheduler`(`learning/scheduler.py`,约 550 行)依赖 pydantic 模型;其核心是:指数遗忘 `retrievability = exp(-elapsed/stability)`、按质量更新稳定度与难度、同一次学习内的重复练习不额外加稳定度、遗忘风险排序。`_resolved_quality` 把 result/hints/attempt 折算成 0..1 质量。
- DT 状态由"证据序列回放"得到(`replay`),不是随手改字段。
- 本机:`pdftotext`、`pdftoppm`、`markitdown`(命令行)、Python 3.13、SQLite FTS5、pydantic 2.12 均可用。DT 的 `deeptutor` 包能否在不装全依赖时被导入,尚未验证。
- `grading.py` 的简答判分是模糊字符串匹配,不采用。

## 2. 值得认真考虑的分歧点

**A. 状态存储:事件日志 vs 直接存状态**
- 事件日志(JSONL 追加,状态由回放得出):与 DT 一致;可审计、可重算、修调度器后能重放历史;代价是回放逻辑。
- 直接存状态:简单,但调度算法一改历史就失真。
- 倾向:事件日志,衍生状态缓存可丢弃重建。

**B. 脚本移植方式:逐行翻译 vs 重新实现**
- 逐行翻译(去掉 pydantic,换 dataclass):黄金向量最容易对上,外部证据最强。
- 重新实现:可能更简洁,但"与 DT 一致"的证明变难。
- 倾向:逐行翻译,保留 DT 的常数与分支,并在 NOTICE 注明修改。

**C. 插件命名与调用方式**
- 插件名 `tutor`,技能名 `kb`/`learn`/`quiz`/`review`,调用为 `/tutor:kb` 等,比 `/tutor:tutor-kb` 简洁。这与 DESIGN.md 中的目录名略有出入,计划里会更新。

**D. 知识点从哪来**
- 没有大纲功能(推迟到 0.2.0)时,出题和复习需要"知识点"。做法:出题时由 Claude 从检索到的片段提取一个知识点名,并带来源页;`ledger` 以(知识库名 + 知识点名)的规范化形式作为 id。
- 风险:同一概念被命名不同导致历史分裂。缓解:出题前先查 ledger 已有知识点名,优先复用;0.2.0 再做正式大纲。
- 知识类型(memory/concept/procedure/design)决定间隔表,由 Claude 在建立知识点时判定并记录。

**E. 简答题判分**
- Claude 按"要点清单"判分:出题时同时生成要点;作答后逐要点判定是否命中,输出 0..1 质量。脚本只记录,不判。
- 风险:判分不稳定。缓解:要点在出题时固定并存档;判分结果与要点一并记录,用户可申诉(重判)。

**F. 引用核对**
- 讲解里的每条原文引用必须能在知识库文本里逐字找到(空白归一后)。DT 用类似思路(`reading/_grounding.py` 的 `selection_range`,以及 `teaching.py` 要求证据必须是学习者原话的字面引用)。
- 转写页(AI 转写)可能本身有误,标记为低置信。

**G. 导入扫描页的额度控制**
- 导入前先统计"无文字页数",告知用户并确认后再转写;可分批,可中断续做,已转写页不重复。
