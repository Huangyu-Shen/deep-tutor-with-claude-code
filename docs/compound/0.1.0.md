# Compound — 0.1.0

What this version taught us. Written after Work, Review and Fix; see `docs/verification/0.1.0.md` for the evidence.

## What worked
- **Golden vectors from the original code** gave a real external check on the port, and the independent review confirmed the port was faithful (no logic defects) even after it found many other problems.
- **A reviewer with a fresh context** found things the author's own tests could not: quote verification that could be fooled, ledger inputs that corrupted the log, skills that contradicted the scripts. 48 findings, most reproduced; the author's 54 passing tests had given false comfort.
- **Running the skills in real Claude sessions** (`claude -p "/tutor:..." --plugin-dir .`) found two problems no unit test could (permission patterns and blocked here-documents) and showed the skills behaving well (refusing to show unverified quotes, asking before spending on scans, not inventing review work).

## What went wrong, and why
- **Tests checked what I thought to check.** The first golden vectors missed 8 of 24 mutants. Lesson: a test suite is only evidence once something tries to break the code; write the mutation check when writing the vectors.
- **I trusted my reading of the original.** I wrote that DeepTutor's error-record rules were unread and later assumed mastery used `quality`; reading `deeptutor/learning/service.py` showed it uses 1.0/0.5/0.0 for unaided attempts only, and graduates an error after one correct retry. Every claim about the original needs a file and line.
- **Verification was lenient by accident.** Using NFKC normalisation and unbounded substring search made "verified" mean less than the README said. A checker that feeds a safety promise must be strict by default and loosened only with a test per loosening.
- **The skills were written before they were run.** Their commands parsed against the CLIs, yet they were blocked at runtime by the permission system. Plan live runs before declaring skills done.
- **My own shell habits cost time**: zsh does not word-split `$VAR` the way bash does, and `cat -A` is not portable on macOS.

## Rules promoted to CLAUDE.md
- Test skills live before calling them done.
- Pass JSON and text to scripts through files in `.tutor/tmp/` and `<`, never here-documents.
- Permission patterns that work: `Bash(python3 *scripts/x.py*)`, `Edit(**/.tutor/tmp/*)`.
- Every claim about DeepTutor's behaviour must be checked in `DeepTutor-main/` with file and line.
- Golden vectors come with a mutation check.
- Anything that backs a trust claim (quote verification, mastery) is strict by default, with one regression test per tolerance.

## For 0.1.x and later
- Real-material trial: one real lecture PDF, one real scanned chapter, to measure transcription cost and quality (the biggest unknown).
- Consider a script for multiple-choice grading and a `quiz` helper that stores keys outside the visible tool call.
- Paraphrase checking is still unsolved: only quotes are verified.
- Marketplace packaging (`marketplace.json`) and install steps.
- Per-skill token cost is small (about 1.1k to 2.2k when invoked); the live runs cost roughly $0.10 to $0.15 each on the Sonnet 5.5 model.
