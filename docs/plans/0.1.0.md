# Plan — 0.1.0

依据:`docs/brainstorms/0.1.0.md`、`docs/DESIGN.md`。**经用户确认后才开始 Work。**

## 约定
- 插件名 `tutor`;技能 `kb`、`learn`、`quiz`、`review`,调用为 `/tutor:kb` 等。
- 脚本仅用 Python 标准库(`pdftotext`、`pdftoppm`、`markitdown` 为外部命令,缺失时给出明确提示)。测试用标准库 `unittest`。
- 脚本一律 JSON 进 JSON 出,出错时返回 `{"ok": false, "error": "..."}` 并以非零退出码结束。
- 数据:`.tutor/kb/<name>/{pages/, index.sqlite, manifest.json}`;`.tutor/learner/<name>/events.jsonl`(追加式事件日志),衍生状态可丢弃重建。
- 讲解默认英文。

## 任务(按顺序,每项有验收标准)

### T1 骨架与法务
- `.claude-plugin/plugin.json`、目录结构、`.gitignore`(含 `.DS_Store`、`.tutor/`)、`LICENSE`(取自 DT 原文)、`NOTICE`(出处、移植文件清单、修改说明)、`README.md`(含对 DeepTutor 的出处与 Apache-2.0 说明)。
- 验收:`LICENSE` 与 DT 的 `LICENSE` 逐字节一致;`claude plugin validate`(或等效检查)通过,若无此命令则加载一次手动确认。

### T2 mastery 与 scheduler 的移植 + 黄金向量
- `scripts/mastery.py`:逐行翻译 `compute_mastery`。
- `scripts/scheduler.py`:逐行翻译 `SpacedRepetitionScheduler` 中 0.1.0 用到的部分(初始状态、`schedule_review`、`retrievability`、`forgetting_risk`、`build_review_queue` 的排序与原因文本、`_resolved_quality`、`replay`);pydantic 模型改为 dataclass。
- `tests/golden/generate.py`(仅开发期使用,需要 DT 源码):用 DT 原代码对固定输入集(含边界:全对/全错/混合/同次重复/长间隔/连错/逾期/带错题)生成 `tests/golden/*.json`,并提交。
- `tests/test_golden.py`:移植版逐项比对黄金向量(浮点用 1e-9 容差)。
- 验收:全部向量一致;`generate.py` 记录所用 DT 的目录与文件哈希。若 DT 包无法在本机导入,改为在脚本内按相同方式提取函数并说明,不降低比对强度。

### T3 ledger(事件日志与衍生状态)
- `scripts/ledger.py`:子命令 `record`(记录一次作答证据)、`state`(回放得到各知识点掌握度与调度状态)、`due`(复习队列)、`errors`(错题列表与状态:active→retrying→review→graduated)、`export`(导出 JSON/Markdown)。
- 事件字段对齐 DT 的 `LearningEvidence`/`ErrorRecord`(`learning/models.py`):result、quality、hints_used、attempt_count、error_type(四类)、self_attribution、ai_confirmation 等。
- 验收:同一事件序列回放结果确定;删除衍生状态后重建结果一致;乱序/重复事件有明确处理并有测试;损坏的日志行被报告而不是吞掉。

### T4 kb(导入、检索、核对)
- `scripts/kb_ingest.py`:按 DESIGN 4.1 分流(pdftotext / markitdown / 文本);生成 `pages/*.md`(每页或每张幻灯片一个文件,含来源元数据);建 FTS5 索引;输出导入报告(页数、无文字页、失败项、跳过项)。扫描页流程:`--plan` 先只统计并列出需要转写的页;`--render-pages` 用 `pdftoppm` 渲染到 `.tutor/kb/<name>/scans/`;转写由技能指引 Claude 逐页看图写入 `pages/`,脚本的 `--register-transcription` 登记并标记"AI 转写"。可分批、可续做、不重复。
- `scripts/kb_search.py`:FTS5 检索,返回片段、文件、页码、是否 AI 转写;支持多个查询词合并去重。
- `scripts/verify_quotes.py`:输入若干(引文, 文件, 页),返回逐条是否在对应页(空白归一后)逐字出现;AI 转写页的结果带低置信标记。
- 验收:用一份有文字层的 PDF、一份 pptx、一份无文字层 PDF 的夹具(`tests/fixtures/`,自制小文件,不含任何第三方版权材料)验证:页码正确、报告准确、引用核对对/错各有用例。中文与特殊字符检索有用例。

### T5 四个技能(SKILL.md)
- `skills/kb`:引导导入、展示报告、扫描页前先告知页数并等用户确认。
- `skills/learn`:改写查询 → 检索 → 英文讲解(类比、定义、例子、常见误解,取自 DT `explain` 提示)→ 附出处 → 调用 `verify_quotes` → 资料未覆盖处明确标注 → 可选费曼检查(简单语言/遗漏/误解)。
- `skills/quiz`:从片段提取知识点(先查 ledger 已有名称并复用)、判定知识类型、出题(选择/填空/简答,含答案、解析、来源页、简答的要点清单)→ 选择题由脚本比对、简答按要点判分 → `ledger record` → 答错时分类四类错因并给补救建议。
- `skills/review`:`ledger due` → 逐项出复习题 → 记录。
- 验收:每个技能的 SKILL.md 描述足以被正确触发;技能只调用上述脚本,不绕过它们直接改 `.tutor/`。

### T6 端到端演练与 0.1.0 收尾
- 用一份自制的小型英文讲义夹具,完整走一遍:导入 → 讲解 → 出题 → 故意答错 → 重测 → 复习队列。留下可复现的记录 `docs/verification/0.1.0.md`。
- 版本号、CHANGELOG、README 使用说明。
- 验收:`python -m unittest` 全绿;演练记录里每一步有真实输出;已知限制如实写入 README(调度器不是校准过的 FSRS;AI 转写可能有误;简答判分是模型判断)。

## 流程节点
1. Plan 确认 →
2. Work(T1→T6,每项完成跑对应测试) →
3. Review:用干净上下文的审查者,重点查:移植是否偏离 DT、事件回放的边界、引用核对的绕过方式、技能是否绕过脚本 →
4. 修复 →
5. Compound:`docs/compound/0.1.0.md`。

## 风险
- DT 包导入需要多余依赖 → T2 验收里已写应对。
- 判分与知识点命名依赖模型判断,存在不稳定 → 用要点固定、复用已有名称、记录判分依据来缓解,不能消除。
- `markitdown` 对 pptx 输出格式未核实 → T4 先看真实输出再定切分规则。
- 技能触发与插件加载细节(目录约定、`${CLAUDE_PLUGIN_ROOT}`)以官方文档为准 → T1 开始前用 claude-code-guide 核实,不凭记忆。
