## Live skill runs (real Claude sessions)

Run with `claude -p "/tutor:..." --plugin-dir <repo> --output-format json` in two scratch projects: a copy of a 0.1.4 `.tutor` tree with no path, and a copy of the 16-PDF course knowledge base (`comsm0126`, 371 pages) used for the 0.1.1 check. Sessions that needed several turns used `--resume`.

### Without an active path (0.1.4 behaviour)

- `/tutor:learn`: answered from the materials with page citations and a labelled general-knowledge part. An early English request came back in Chinese; after the language rule was strengthened, a rerun answered in English. No permission denials.
- `/tutor:quiz`: wrote two cited questions on requested topics, reused the knowledge points already in the ledger, and said there was no active path. No denials.
- `/tutor:review`: reported 0 tracked items and 0 due, named the next step, and invented no work. No denials.

### With a path, on the real course

1. `/tutor:path` drafted a path from the goal "COMSM0126 three-week plan": 8 modules, 37 knowledge points, every point with a `source_id` and page. Nothing was saved; the model surfaced that the materials say the unit has no exam and added a case-study module instead. One denial (see below).
2. `save --activate` validated and wrote `p_80304c02` (8 modules, 37 points) and activated it. A later save of the same outline detected the existing path and stopped instead of overwriting it.
3. Diagnostic: 5 questions, easy to hard, each cited and verified. Status after the diagnostic: M1 still `available`, M2 still `locked`, diagnostic mastery visible (0.5–0.8) with `unaided 0`; no module became `in_progress` and nothing unlocked.
4. Exemption for M1: workload announced first (four quiz questions on the one memory point, one explanation for each of the three concept/design points), then 4 quiz answers and 3 Feynman explanations, all cited, `origin: exemption`. Status then: M1 `mastered`, M2/M3/M7 `available`, M4–M6 and M8 still `locked`.
5. `/tutor:learn` on a topic inside M4: refused with `locked_by: M2`, named the next module and point, and offered review (which ignores locks) or deactivating the path.
6. `/tutor:quiz` in a small path project: picked the path's available knowledge point, wrote two questions, did not re-register the point.
7. `/tutor:learn` on a `concept` point: taught the point, then required a Feynman explanation before any gate could pass. An English request produced an English lesson.

## Findings from the live runs (fixed)

1. **Every answer was recorded twice.** The course log held 10 diagnostic events for 5 question ids and 14 exemption events for 7. A retried write duplicated the evidence and could have doubled a gate. `path.py` now counts one attempt per `question_id` in gates and in `unaided_attempts`; an unaided answer outranks a hinted retry of the same question, so a retry cannot erase the original evidence. Regression tests cover a duplicate record and a hinted re-answer. The log format is unchanged.
2. **Diagnostic answers were counted as unaided attempts.** Status showed `unaided 2` from diagnostic-only points, which contradicted the rule that a diagnostic only locates a starting point. `unaided_attempts` and `last_unaided` now exclude `origin: diagnostic`; mastery still shows it. Regression test added.
3. **`sqlite3` and pipes were refused by the pre-approved permissions** (see above). Fixed in the skills.
4. **Language did not follow an English request** in one `learn` run. The rule now states that an English request gets English output even when the skill file or earlier sessions are in another language; verified by rerun.

Observation, not a defect: one save session reused the file name `.tutor/tmp/outline-1.json` although the skill says to use a new name. It noticed the path already existed and made no changes, so nothing was lost; the rule is procedural and not mechanically enforced.

## Review pass (ce-code-review)

Eight reviewers (correctness, testing, maintainability, standards, adversarial, python-api, agent-native, learnings) read the 0.2.0 diff; findings were fixed before release, each with a regression test where the behaviour is testable:

- A failed exemption left the module `in_progress` and `exemption_available: false`; it now stays `available`, so the promised no-cooldown retry is reachable (test: `test_a_failed_exemption_leaves_the_module_available`).
- A hinted retry of the same `question_id` replaced the unaided answer; unaided evidence now outranks it (test: `test_a_hinted_retry_does_not_erase_unaided_evidence`).
- A hinted Feynman explanation passed a `concept`/`design` gate; hints now disqualify it (test: `test_a_hinted_feynman_retelling_cannot_pass_a_concept_gate`).
- An `incorrect` qualitative record on a `memory` point could be hidden by labelling it qualitative; it now blocks the numeric gate (test: `test_a_qualitative_failure_blocks_a_numeric_gate`).
- Attempts without a `question_id` could satisfy the three-unaided rule; they now count for mastery display only (test: `test_attempts_without_a_question_id_do_not_open_a_gate`).
- `resolve` allowed a point that had already passed and ignored broken evidence; it now returns `already_passed` and `evidence_invalid` (tests: `test_resolve_rejects_invalid_evidence`, `test_resolve_rejects_an_already_passed_point_inside_an_open_module`).
- A dangling active pointer blocked every command with no in-tool repair; `deactivate` now tolerates and clears it, and every store command requires an ingested knowledge base (tests: `test_deactivate_is_the_repair_for_a_dangling_pointer`, `test_unknown_kb_is_rejected_and_creates_no_store`).
- `load_store` checked less than `validate`; one structural checker now runs on both stored definitions and an outline being saved, including evidence entries, timestamps and `active_path_id` (test: `test_half_damaged_store_is_rejected_without_writing`).
- Non-UTF-8 log lines and unknown `origin` values failed or silently vanished; they are now reported as warnings while the rest of the log is read (tests: `test_a_non_utf8_log_line_is_reported_and_skipped`, `test_an_unknown_origin_is_read_but_never_opens_a_gate`).
- `status --all` and `affected_modules` were added so R23 and KTD8 are reachable from the CLI; `status`/`resolve` were verified read-only (tests: `test_status_all_reports_every_path`, `test_save_and_validate_report_affected_modules`, `test_status_and_resolve_are_read_only`).
- Documentation and metadata were corrected: README and CHANGELOG now state the monotonic `mastered` rule and `regressed`, the path skill's example outline validates, the diagnostic and exemption steps name the `ledger.py now` stamp and every `record` command, `marketplace.json` mentions the learning path, and NOTICE lists the path attribution and deviations.

Two more real sessions checked the fixes: `/tutor:path show me the status of every path` on the course copy rendered all eight modules from `status --all` with `permission_denials: []`; on a copy whose active pointer was replaced with `p_missing`, `/tutor:path the path status is failing, please fix it` ran `deactivate`, cleared the pointer and left the definitions intact, again with no denials and no hand-editing of `.tutor/`.

## Deviations from the plan

1. `--learner` is accepted both before the command (as `ledger.py` does) and after `status`/`resolve` (as the KTD7 table writes it).
2. Gate replay deduplicates `question_id`; this is stricter than the plan and was added after the live runs (finding 1).
3. `unaided_attempts` excludes diagnostic events explicitly; KTD3 said diagnostic only counts for mastery display, and the counter now follows the same rule.
4. The skills forbid `sqlite3` and shell pipes; the plan did not mention it, but the pre-approved permission set does not allow either.
5. `status` and `resolve` return `mastered_at`, `locked_by`, `invalidated_by`, `progress` and `next_action` as planned; no extra state is persisted.
6. `status --all` was added for R23; `affected_modules` was added to `validate` and `save` for KTD8.
7. `in_progress` counts attempts from every eligible origin except `exemption` and `diagnostic`, so a failed exemption leaves the module `available` (R14) and a diagnostic never opens a module (AE3).
8. An unknown `origin` read from a log is kept (and warned about) but never opens a gate; this keeps older or third-party logs readable without trusting an unknown origin as evidence.
9. A mastered module reports points that no longer pass under `regressed` while `missing` stays empty; this is the planned monotonic behaviour (KTD3), and the README and CHANGELOG now state it.
