## Review pass (ce-code-review)

Five reviewers (correctness, testing, adversarial, python-api, skill/standards) read the 0.3.0 diff in a clean context. Findings fixed before release, each with a regression test where the behaviour is testable:

### Correctness

1. Every format required a non-empty `answer`, although the plan and quiz skill allow a short-answer question to be graded by its checklist. Now a short answer may carry either; multiple choice and fill-in-the-blank still need an answer (tests: `test_short_answer_may_carry_only_a_checklist`, `test_short_answer_without_answer_or_checklist_is_rejected`, `test_multiple_choice_requires_an_answer`).
2. Prompt normalization kept control whitespace, so `"A B"` and `"A\nB"` were stored as two questions while the empty bigram set made the similarity 0. All whitespace is now removed before comparison (test: `test_prompts_differing_only_in_control_whitespace_are_duplicates`).
3. A non-string `answer_status` made `read_events` drop the whole attempt, losing it from mastery, errors and the schedule. `answer_status` is now validated on write only, so a malformed value costs the gate, never the record (test: `test_a_non_string_answer_status_keeps_the_attempt_on_read`).
4. `schema_version` compared with `!=`, so `true` and `1.0` passed as version 1. Only a real integer is accepted (test: `test_schema_version_must_be_a_real_integer`).
5. `allow_near_duplicate` used `bool()`, so the string `"false"` enabled the override. It must now be a JSON boolean (test: `test_allow_near_duplicate_must_be_a_boolean`).
6. `citation_ok` defaulted to true when missing and accepted truthy non-booleans. It must now be exactly `true` to be picked, and a missing or non-boolean value is reported as damage (test: `test_missing_or_non_boolean_citation_ok_is_damaged`).

### Skill and standards

7. Section 2b used `<stamp>` and `<recorded.kp>` before either was defined. It now starts by taking the stamp and registering (or reading) the knowledge point.
8. Review never called `revalidate`, so an invalidated question could never return after the page was rebuilt. It now checks `bank.py list` for `citation_ok: false` and revalidates when the quote verifies again.
9. The bank had no browsing flow: `bank.py list` appeared without `--kb`, and `references` was unused. A 2c section now documents both with their filters.
10. "The answer key lives in `.tutor/quiz/`" was false for reused bank questions. The rule now names both locations and the `get --with-answers` read.
11. Review did not pass `--exclude-question-id`, so the same oldest question could be picked on every visit. It now keeps the session's used ids and passes each one.
12. Review had no safe way to check whether a question was already in the bank; a plain `get` (without keys) is now the documented check.
13. When a knowledge point already existed, `recorded.kp` did not exist; the skill now says to take the id from `ledger.py state`.
14. Both skills now say that a permission refusal must stop the step and be reported, rather than retrying under another file name or skipping the record.

### Findings fixed from the earlier review round

- `add` no longer loses a whole batch to one duplicate: clean questions are stored, exact duplicates go to `rejected`, near-duplicates to `near_duplicates`; only a structural error fails the batch before writing.
- `path.py` uses a whitelist for gate evidence: only a missing `answer_status` or `sourced` counts; `unverified` and unknown values never open a gate.
- A mimic question must keep the reference's format and difficulty.
- Knowledge point ids must be spelled exactly as `learner_log.kp_id` normalizes them.
- `add-reference` ignores `confirmed_at` when comparing, so a re-submission after a second boundary is still `existing` and keeps the first timestamp.
- A damaged stored entry is rejected at read time (missing fields, id/key mismatch, invalid `options`, `citation_ok`, timestamps).
- The temporary bank file is deleted if writing fails.
- `_bigrams("")` returns an empty set instead of `{""}`.

## Deviations from the plan

1. `add` is partially successful for duplicates. U1's test scenario read as "reject", but a hard batch failure would make one overlapping prompt discard every clean question in a session; the contract now names `rejected` and `near_duplicates` explicitly.
2. The gate filter is a whitelist rather than "exclude `unverified`". Unknown values are also excluded, which is stricter than KTD4 and safer; the plan text was updated.
3. A `short_answer` question may store a checklist without a model answer, matching the quiz skill. U1's "answer or checklist" wording is now enforced per format.
4. `allow_near_duplicate`, `citation_ok` and `schema_version` are type-strict. This is stricter than the plan and was added by the correctness review.
5. The quiz skill gained a browse section (2c); the plan's U3 mentioned browsing but had no procedure.
6. Review keeps a session list of used question ids and revalidates recovered citations; both were implied by R14/R16 but missing from the draft steps.
7. Path diagnostic and exemption questions are recorded in the ledger only and are not added to the bank; `CONCEPTS.md` now states this.
