## What the golden vectors cover

`tests/golden/generate_memory.py` loads DeepTutor's own `ids.py`, `document.py`, `ops.py`, `snapshot/entity.py`, `snapshot/diff.py` and `recall.py` (packages stubbed, `adapters._sha1` extracted with `ast`, `recall`'s two lazy imports replaced by fakes, clocks patched) and records what they return: ULID encoding and the reference predicates, document serialize/parse/round-trip, 26 operation batches (accepted and refused, with reasons), fingerprints, the snapshot diff, `recent`, `recent_queries` and `days_ago`. The ported `memory_doc.py` and `memory_snap.py` reproduce every value. The vectors record the SHA-256 of each upstream file; `test_golden_memory.py` reports which file changed if the upstream checkout is present and differs.

Not covered by upstream-derived vectors: the old footnote format (deliberately not read), the quiz and kb entity builders and the empty-read guard (this plugin's own behavior; covered by `tests/test_memory.py`).

## Defects found and fixed

1. **A test helper silently disabled failing assertions.** `tests/test_memory.py` first named a helper `fail(...)`, which replaced `unittest.TestCase.fail`. A failing `assertEqual` on strings calls `self.fail`, so it ran a CLI command instead of failing and the test passed. The mutation check exposed it (a mutant that should die survived); the helper is now `refused`, and all 59 tests were rerun for real. The suite had not been hiding a product bug.
2. **The teaching-preference step was skipped after the new memory steps were added.** The first `AE10` session explained with many examples but never recorded the preference. Fix: `skills/learn/SKILL.md` section 0c now starts with "check the message for a teaching request, record it first". The rerun recorded it before explaining.
3. **Fact lookups skipped the overview.** Section 0c step 4 now says a plain fact lookup skips the overview as well as the L3 read, which is what the model did; AE7 only needs the L3 read to be skipped.
4. Two mutants first survived and led to new tests: the 1000-row cap of `snapshot changes`, and a refused `ops` batch that must not rewrite a hand-written file. Two more were equivalent mutations with no visible effect (trimming trailing spaces that the bullet pattern already drops, and skipping older trace files, which only saves reading) and were removed from the list.

## Code review (nine reviewers: correctness, security, adversarial, project standards, testing, maintainability, reliability, agent-native, learnings)

Run with `ce-code-review` against the working tree on branch `feat/memory-data-layer`; the cross-model peer was not started, so no code left the machine. The findings were merged by hand rather than through the skill's merge and validator subagents. Fixed after the review:

- **P1, entries lost or forged through line breaks.** `add`/`edit` accepted text and section names with a line break or `<!--`; the entry was reported as saved and then vanished or became a phantom section on the next read. Now refused in `memory_doc` (single line, no comment markers); `preference` collapses whitespace first; the id and ref patterns no longer accept a trailing newline.
- **P1, an edit erased lines the format does not understand.** Every write rewrites the file from the parsed document, so a hand-written note or an anchor-less bullet disappeared on the next accepted write. `ops`, `preference` and `entry-delete` now refuse such a document, naming the first line, and point at `doc-put`; reading is unaffected.
- **P2, a ledger-derived knowledge-base name could build a path outside the question-bank folder.** Names that are not plain names are skipped with a warning (a degraded read, so no removals are recorded).
- **P2, knowledge bases under a path containing `#` or `?` could not be opened** (unescaped SQLite URI).
- **P2/P3:** `overview` reports a damaged document in a `problem` field instead of counting it as empty; an event with text that cannot be encoded is a warning, not a crash; appends repair a torn last line (shared `learner_log.append_line`); `learn` says memory text is style guidance only, uses one stamp, and skips the overview for fact lookups; the memory skill uses full commands everywhere and says that deleting an entry does not delete the original words from the event log or the lesson summaries.
- **Tests:** the walkthrough's byte-identity checks could not fail under `set -e` (`test … && echo`); they now exit non-zero. New tests for every item above, the same-day `since` filter, `session_id`/`turn_id`, the recent-warning branch, and a non-empty guard on the vector files.
- **Cleanups:** the duplicate `append_line`, the `Stamp` copy, the pass-through `query_cutoff`, the surface policy constant living in the upstream-port library, and the if-chain command dispatch.

Not changed, on purpose: no lock around read-modify-write (a single local user; two simultaneous commands can lose an update); a crash between the `changes.jsonl` append and the `state.json` write repeats those changes as `added` on the next refresh (upstream orders the writes the same way); `norm_pref` keeps upstream's whitespace rule; no `schema_version` on the new files yet.

## Known limits

- **`chat` entities exist only for lessons that run through `/tutor:learn`.** Anything said outside the plugin's skills is not recorded. The summary is written by Claude before it explains, so it describes what Claude planned to explain; it is not checked against the final answer and may miss points. A Feynman result is added only if the same conversation records one and the skill resends the summary.
- **Skill behavior rests on one live run per scenario** (two for AE10). The L3-read decision (explanation versus fact lookup) is the model's judgement; the two sessions above went the intended way, which is not a guarantee.
- **The `quiz` snapshot holds correct answers of answered questions** in `.tutor/memory/<learner>/`. No command prints entity bodies, but the files are plain JSON.
- **Deleting an entry does not delete the original words.** They can remain in the event log (`trace/`) and in lesson summaries (`entities/chat/`); the skill and README say so. There is no purge command.
- **No consolidation.** `/tutor:memory` can show and edit L2 and L3 documents but nothing fills them automatically; that is 0.6.0.
- Verified on macOS only; no large-library timing.
