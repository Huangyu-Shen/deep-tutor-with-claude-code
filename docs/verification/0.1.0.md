## Golden vectors (external evidence)

`tests/golden/vectors.json` was generated by running DeepTutor 1.6.15's own `mastery.py` and `scheduler.py` (SHA-256 of the sources recorded in `meta`): 18 mastery cases, 252 replay cases (4 knowledge types, 21 event sequences, 3 retention targets), 12 review-queue cases. The ported scripts match all of them within 1e-9, including reason strings and queue order.

The first version of the vectors left 8 of 24 hand-made mutants alive (found in review: same-session failure paths, the qualitative branch, window and quality boundaries). Scenarios were added for each and `tests/golden/mutation_check.py` keeps the check repeatable; now 19 of 19 mutants are killed.

Not covered by the vectors and not reachable from the ledger: `hydrate` of legacy states, `replay(initial_state=...)`, retention-target validation. The ledger always uses retention 0.9, so the 0.8 and 0.95 vectors only protect the ported code, not production behaviour.

## Live skill runs (real Claude sessions)

Run in a scratch project with the four fixture files. These were the first runs of the SKILL.md files by a fresh session, and they found two problems that tests could not:

1. `allowed-tools: Bash(python3 *scripts/kb.py *)` did not match the expanded command (the path is quoted), so the first run was denied. `${CLAUDE_PLUGIN_ROOT}` itself expanded correctly. Fixed with `Bash(python3 *scripts/kb.py*)`.
2. Claude Code refuses shell here-documents whose body contains braces and quotes ("expansion obfuscation"), which blocked every JSON payload. The skills now write the payload to a new file under `.tutor/tmp/` and pass it with `<`. A plain `Write(...)` permission rule did not match the absolute path the tool uses; `Edit(**/.tutor/tmp/*)` does.

Results after the fixes:
- `/tutor:kb bio materials/`: ingested, reported all four files, flagged the two scanned pages and asked before transcribing. No permission denials.
- `/tutor:learn bio What does Rubisco do?`: searched, wrote the quotes file, ran `verify` (status `verified`), then answered with a labelled "Beyond your materials" part. In an earlier run, when the quotes file could not be written, it dropped all direct quotes and said so instead of showing unverified ones.
- `/tutor:quiz bio Calvin cycle and Rubisco, 2 short questions`: wrote the quiz file, registered knowledge points, asked Q1 without showing the key. After a wrong answer ("A") it graded against the stored key, diagnosed `deviation`, recorded the attempt with the stamped question id and the question text, and moved to Q2.
- `/tutor:review bio` with nothing due: said so, gave the next review date, and did not invent work.

Permission scope: a skill's `allowed-tools` only applied during the skill's own turn. In a resumed conversation the next turn's file write was declined, and Claude correctly said the result was not recorded. Documented in the README (Permissions) with a settings snippet.

## Review findings

An independent reviewer (fresh context) reported 48 findings; the port itself was judged faithful (no logic defects). All major findings were reproduced or confirmed against the code, fixed, and given regression tests:

- Quote verification: ellipsis could hide a reversed meaning (now `verified_elided` plus `skipped_text`); matching had no word boundaries (`0.05` matched `0.055`); NFKC folded `mc²` into `mc2`; line-end hyphens and dashes; CJK length and spaces.
- Ledger: NaN/Infinity/huge numbers, wrong field types and `null`s corrupted the log or crashed every later command; a half-written last line swallowed the next event; the event is now replayed before it is written, appends are fsync'd, and every error returns JSON.
- Mastery now counts unaided attempts only and scores partial as 0.5, as DeepTutor does (`deeptutor/learning/service.py`), instead of using the explicit quality.
- KB: an unreadable file rolled back the whole batch; stale cached page images after a file changed; a scanned page with a text footer counted as text; quadratic FTS deletes; locked database on concurrent runs; duplicate files; Chinese file names got meaningless ids; Python 3.9 crash (`zip(strict=True)`).
- Skills: question ids restarted at `q1` every sitting (now stamped), review could never graduate a mistake (now re-asks the original question), epoch times replaced by ISO dates and a `now` command, hint and threshold wording corrected, verify uses `source_id`.
- Notices: DeepTutor's copyright line added to NOTICE; per-file adaptation notices; documented deviations.

Left as known limits (not fixed in 0.1.0):
- `verify` accepts a line-end hyphen joined as one word (`wellknown`), because PDF layout needs the joined form for words like `photo-synthesis`.
- A paraphrase with a page number is not checked, and nothing forces a model to call `verify`; it is an instruction in the skill, observed to be followed in the live runs.
- The quiz answer key is written with the Write tool, so it is visible if the user expands that tool call.
- Knowledge-point `sources` can point to old page numbers after a file changes; no re-linking.
- CJK search uses substring scans and mixes its scores with BM25 scores; a search query that starts with `-` needs `--query=-x`.
- Slides that are only pictures are reported as having no text and are not indexed; there is no transcription path for them.
- Multiple-choice and fill-in-the-blank grading is done by Claude comparing to a stored key, not by a script as the plan first said.

## Not verified

- Larger inputs: only tiny fixtures; no timing or memory data on a real textbook beyond a 3,000-unit ingest in under a second (reviewer measurement).
- Windows or Linux.
- Transcription quality on real scans (handwriting, tables, formulas). The test scan is clean printed text.
- Marketplace installation (not published yet).

## Deviations from the plan (docs/plans/0.1.0.md)

1. One script `kb.py` with subcommands replaces `kb_ingest.py`, `kb_search.py` and `verify_quotes.py`.
2. Pages live in the SQLite file only; no `pages/*.md` mirror.
3. `ledger.py` keeps no cached derived state; it replays the log on every call.
4. `ingest` always runs and reports pages needing transcription; there is no `--plan` mode.
5. Error graduation needs two consecutive correct answers; DeepTutor graduates after one (checked in `deeptutor/learning/service.py`).
6. The scheduler port omits `set_desired_retention` and the `LEARNING_DEBUG` switch; `get_due_tasks` and the protocol are not ported.
7. Payloads reach the scripts through files in `.tutor/tmp/`, not here-documents (see live runs).
8. Multiple-choice grading is by Claude, not a script.

## Addendum: first real course (0.1.1)

16 PDFs from one course (371 pages) were ingested in about 1.2 seconds. With the 0.1.0 rule 121 pages (33%) were flagged as scans; looking at them showed a 3D reconstruction photo, an empty video placeholder and title slides, none of them text. Fixed in 0.1.1 (document-level ratio 0.8, `--scanned` override, `scan_check` in the report); the same ingest now flags 0 pages and lists 25 pages with no text. Search over the ingested course returned sensible pages for "immersion presence" and "empty machine" queries. Reviewed with `ce-code-review` (focused depth, local adversarial reviewer; no code was sent to another provider): 3 P2 findings, all fixed with tests, one residual risk accepted (the 0.8 ratio was tuned on one course).
