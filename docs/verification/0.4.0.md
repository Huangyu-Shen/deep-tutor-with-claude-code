### Defects found and fixed in the live runs

- **The preference was not recorded in the first AE1 run.** The record step sat after the explanation, and the one-turn session ended once the explanation was written, so the model followed the preference but never saved it. The skill now says that when the learner's current message already holds a preference or a "did not help" remark, record it before explaining (`skills/learn/SKILL.md` section 0b, step 4). A rerun recorded it.
- **Entries were written in English for a Chinese learner.** The skill now says to write `text` and `strategy` in the learner's language; `evidence` stays exactly as written. The later sessions (observation, forget) were run after this change and wrote Chinese; the preference saved in the first rerun is still English text, and that is a leftover from before the change, not a defect of the final skill.

### Observations, not defects

- `teaching.py show` was called twice in some sessions (before and after the search, as the skill allows). It is read-only.
- Registering a knowledge point to record an observation adds a `kp_define` event to the ledger. It adds no attempt, so mastery, errors and the review queue are unchanged; the walkthrough and tests check that recording itself never touches the ledger.

## Code review

A seven-reviewer `ce-code-review` of the working tree found no P0 or P1 issue and one confirmed P2: when a profile was full, the skill asked which entry to remove but could not save the new entry, because its quote was no longer in the current message. The skill now has the learner restate the new request in the same reply and sends a combined remove-plus-add batch (covered by a unit test). Also fixed from the review: the skill runs `list` before forgetting an entry, tells the learner where a damaged profile lives and how to clear it, `show --kp` rejects a non-canonical knowledge point id, and tests were added for damaged stored entries, the evidence length cap, removing an observation, trimmed evidence and a knowledge point registered in another knowledge base. The remaining review notes (for example that the quote rule accepts any verbatim substring) are recorded as known limits below.

## Known limits

- The quote rule enforces the format, not truth: the script checks that `evidence` appears in the `learner_message` it is given, and that message is passed in by Claude.
- The skill's reading, recording and announcing steps are instructions, not enforced by a script. They were exercised in the sessions above, but a different phrasing of a learner's message could still lead the model to skip a record; the script refuses only a record that lacks a verbatim quote.
- Two Claude sessions writing the same profile at the same moment can lose one update (atomic replace, no locking). Single-user, low-frequency use makes this unlikely and it was not tested.
- Not re-run on other operating systems. Not run with a learning path active; the path branch of the skill's knowledge-point lookup reuses `path.py status`, which was not exercised in these sessions.
